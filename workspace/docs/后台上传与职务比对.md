# 后台上传与职务比对

> 适用任务：上传规范化人物数据、获取后台在线比对数据、筛选无重复职务以及生成规范化复核表。

## 一、流程与入口

第四阶段固定按以下顺序执行：

1. `script4-职务比对1-上传官员信息.py`
2. `script4-职务比对2-获取在线比对数据.py`
3. `script4-职务比对3-获取无重复数据.py`
4. `script4-职务比对4-无重复数据规范化.py`

上传属于外部写入操作，不纳入普通爬取或职务规范化的一键自动运行。只有用户明确要求上传时才能执行第一步。离线测试、迁移验收和代码检查不得调用真实上传接口或在线比对接口。

## 二、固定输入输出

1. 上传输入固定为项目根目录下的`职务规范4：扩充.txt`，不得扫描目录或自动选择其他TXT。
2. 在线比对结果固定写入项目根目录下的`职务比对2：在线比对数据.txt`。
3. 无重复职务结果固定写入项目根目录下的`职务比对3：无重复数据.txt`。
4. 最终人工复核表固定写入项目根目录下的`职务比对4：无重复数据规范化.xlsx`。
5. 日志统一写入`workspace\log\职务比对`。

## 三、上传数据契约

1. 上传脚本必须先验证输入文件符合现行十二列表头及列序。
2. 后台上传文件在内存中生成，不依赖外部Excel模板。
3. 后台导入固定使用七列：`姓名、职务、依据说明、依据链接、排序、所属省、所属市`。
4. 上传脚本一次只处理根目录下的一个规范化结果文件，不递归扫描目录，不上传历史结果或其他TXT。
5. 后台返回的导入、重复跳过和校验失败统计必须写入日志；校验失败明细不得静默丢弃。

## 四、认证与浏览器边界

1. 登录令牌固定保存在`.secrets\official_update_token`，不得写入源码、日志、报告或Git。
2. 后台登录使用独立浏览器目录`.official_update_chrome_profile`和调试端口`9777`，不得与爬虫使用的`.chrome_cdp_profile`混用。
3. 令牌缺失或失效时，脚本可以启动专用Chrome并等待用户自行登录；不得保存账号和密码。
4. `.secrets`和后台专用Chrome目录必须保持在`.gitignore`中。

## 五、完整性与失败处理

1. 获取在线比对数据时，任一分页失败或实际记录数与接口声明总数不一致，必须终止且不得覆盖现有结果。
2. 筛选阶段只按明确的职务元素完全相同规则判断重复，保持同类型记录的原始顺序。
3. 规范化关联无法唯一确认时不得凭常识补造人物、职务或机构；应保留为空或进入人工复核。
4. 中间TXT使用UTF-8编码和制表符分隔；最终XLSX只用于人工复核，不作为上游权威业务源。

## 六、验证要求

修改第四阶段脚本后至少执行：

1. AST语法解析和`py_compile`；
2. 十二列输入到七列内存Excel的字段映射测试；
3. 令牌路径和后台专用Chrome路径检查；
4. 在线比对分页不完整时拒绝覆盖的测试；
5. 无重复筛选和规范化关联的离线样本测试；
6. 全项目旧`people_update`绝对路径和旧文件名残留扫描。
