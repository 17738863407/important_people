# 数据与输出契约

> 适用任务：修改规则主表、业务字段、脚本或结果命名、依据链接、详情页链接、十二列输出及相关校验。执行这些任务前必须完整读取本文。

## 一、权威业务源

`workspace\source_data\规则主表.txt`是生产运行、新脚本生成和业务字段维护的唯一权威业务源，固定十二列且不得擅自增删或调序：

```text
组织体系	目录链接	机构类型	机构层级	所属省*	所属市	机构名称	机构别称	官网链接	领导链接	脚本序号	备注
```

1. `脚本序号`统一为四位数字，是规则主表、页面脚本和输出结果之间的唯一关联键，不得重复。
2. 对页面脚本和人物输出而言，机构名称、机构别称、目录链接、官网链接、领导链接、所属省、所属市、组织体系、机构类型、机构层级和业务备注以规则主表为准；`workspace\source_data\机构主表.txt`是独立的机构目录业务表，不直接覆盖规则主表。
3. 页面脚本不得重复保存`organization`、入口`url`或其他业务源副本；运行器按脚本序号注入业务字段。
4. 规则主表读取必须经过`crawler_core.rule_table`的表头唯一性、逐行列数、必填字段、机构别称格式、脚本序号唯一性和枚举校验。
5. `领导链接`允许留空；有值时必须表示机构领导信息入口页。域名从非空领导链接解析，不在主表重复维护。
6. 历史Excel、旧输出、历史报告和快照不是生产业务源，不得用于生成脚本或覆盖规则主表。

## 二、业务字段规则

1. 规则主表的机构分类和记录物理相对顺序以项目内`workspace\source_data\机构主表.txt`为来源，同一机构的多条规则保持原相对顺序。
2. 分类同步以四位脚本序号为稳定主键；自动同步不得覆盖人工确认映射，名称冲突、未匹配和多目录归属必须保留复核依据。
3. `组织体系`使用机构全表定义的13种体系：`中共中央、全国人大、国务院、全国政协、最高人民法院、最高人民检察院、民主党派、群团组织、省级四大、省厅领导、地级四大、市局领导、央企`，以及司法与纪检监察机关体系值`法院、检察院、纪委监委`和业务兜底值`其他`；无法确认时允许留空，不得猜测。`其他`记录排在现有体系之后。
4. `机构类型`必须复制机构全表中的现有值；源表没有机构直接记录时允许留空，不得根据相似机构虚构。
5. `机构别称`允许为空；多项统一使用中文顿号`、`分隔，不得含空项、重复项、机构全称或未经确认的推测性简称。
6. `备注`只允许填写`空缺占位`、`两个机构一块牌子`或留空；过程批次、迁移状态、任务登记和技术画像不得写入。
7. 页面类型、加载方式、抽取模式、采集器、解析器、选择器、接口字段、详情策略、置信度和风险说明只在对应页面脚本维护。

## 三、脚本与结果命名

1. `site_adapters`及其全部子目录中的页面脚本命名为`四位脚本序号_机构名称.py`。
2. 单脚本抽取结果命名为`四位脚本序号_机构名称.txt`，脚本与结果除扩展名外必须完全相同。
3. 脚本序号与机构名称只能从规则主表取得；页面类型、加载方式、域名、采集方式、解析器和模型标签不得写入文件名。
4. 文件名安全转换统一经过`crawler_core.naming`，脚本生成器、运行器和核验工具不得复制各自的命名公式。
5. 规则主表中的机构名称变化时，必须同步原地重命名对应脚本；不得保留旧机构名制造同序号副本。

## 四、十二列输出

固定表头为：

```text
姓名*	职务*	排序*	职级*	所属省*	所属市	依据链接	依据说明	维护人	机构	详情页链接	脚本序号
```

| 字段 | 爬虫阶段规则 |
|---|---|
| 姓名* | 按当前页面可验证结构提取 |
| 职务* | 留空，交给后续职务规范化 |
| 排序* | 按网页、表格、接口数组或图片版面的原始人物顺序，从1开始 |
| 职级* | 留空 |
| 所属省* | 从规则主表按脚本序号注入；主表为空时留空 |
| 所属市 | 从规则主表按脚本序号注入；主表为空时留空 |
| 依据链接 | 规则主表中的机构领导信息入口页 |
| 依据说明 | 当前人物对应的原始职务证据经过允许的确定性基本清洗后生成 |
| 维护人 | 留空 |
| 机构 | 从规则主表注入 |
| 详情页链接 | 仅填写与当前人物一一对应的真实独立人物页 |
| 脚本序号 | 四位脚本序号 |

补充要求：

1. 旧解析结果的`duty`由公共运行器转存到`evidence/依据说明`，最终`职务*`冻结为空。
2. TSV单元格必须清除制表符、回车和换行，文件使用UTF-8编码和`.txt`扩展名。
3. 单脚本失败时仍生成同名十二列TXT，并在`依据说明`写明`抽取失败：具体原因`；不得静默失败或删除最终失败结果。
4. `outputs`只存放抽取结果；运行清单、审计、比较和质量报告放入`workspace\reports`，日志放入`workspace\log`。
5. 旧八列表头只用于识别历史结果，不是现行生产契约。

## 五、依据链接与详情页链接

1. `依据链接`及内部`row.url`取自规则主表；非空时必须表示机构领导信息入口页，规则主表未提供领导入口时允许留空。
2. `detail_url`及`详情页链接`只表示与当前人物明确对应的独立人物详情页、个人简介页或真实可点击人物卡片页。
3. 详情页链接必须从当前网页列表项、人物卡片、接口字段或其他可验证结构动态提取。
4. 以下情况详情页必须留空：
   - 页面没有人物详情页；
   - 链接等于依据链接或最终入口页；
   - 链接是栏目页、机构主页或列表页；
   - 链接是`#`、当前页锚点、`javascript:`或`mailto:`；
   - 无法证明链接与当前人物一一对应。
5. 公共运行器的URL纠偏只是防错兜底，不能代替页面脚本的正确实现。

## 六、顺序与字段职责

1. 输出顺序继承列表页DOM、表格行、接口数组或图片版面阅读顺序。
2. 列表转详情可以并发抓取，但每个候选必须保留原始列表索引，并在导出前恢复原始顺序。
3. 禁止按详情文件名、姓名、拼音、URL、字典序或任务完成时间排序。
4. 不在原目录中的异常人物如必须保留，应置于末尾并标记人工复核，不得破坏已确认顺序。
5. 爬虫阶段不推断规范职务、职级和排序；所属省、所属市只从规则主表注入。
6. 职务规范化固定依次执行“合并—清理—补全—扩充”，具体规则以`workspace\docs\职务规范处理规则.md`为准。

## 七、修改验收

修改本文覆盖范围内的代码或数据后，至少检查：

1. 十二列表头、列序、必填字段、机构别称、枚举和脚本序号唯一性。
2. 脚本文件名、输出文件名和规则主表记录的一致性。
3. 十二列表头、列序、UTF-8编码和TSV单元格清理。
4. 依据链接、详情页链接和人物顺序符合上述语义。
5. 失败结果被显式保留，且没有把历史八列结果混入生产输出。
