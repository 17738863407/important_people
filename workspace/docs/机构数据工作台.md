# 机构主表与数据工作台

机构主表与规则主表暂时保持为两个独立业务表，但统一使用以下十二列字段和顺序：

```text
组织体系	目录链接	机构类型	机构层级	所属省*	所属市	机构名称	机构别称	官网链接	领导链接	脚本序号	备注
```

## 文件位置

- 机构主表：`workspace\source_data\机构主表.txt`
- 工作台程序：`workspace\institution_catalog\workbench`
- 工作台数据库：`workspace\institution_catalog\workbench\data\institution_workbench.db`
- 网页发布前备份：`workspace\source_data\backup\机构主表\web_edits`
- 启动入口：项目根目录 `启动机构数据工作台.ps1`
- 机构维护脚本：`workspace\institution_catalog\maintenance`
- 机构目录原始资料：`workspace\source_data\机构目录`
- 机构目录网页快照：`workspace\snapshots\机构目录`
- 机构维护日志：`workspace\log\机构目录`
- 机构维护报告：`workspace\reports\机构目录`

## 字段口径

- `机构名称`分别保留两张表当前名称，本次迁移不统一名称、不合并记录。
- `脚本序号`是两张表之间唯一的正式关联键；四位序号表示已关联，空值表示尚未关联。
- 机构主表原字段`主表匹配`已取消。旧标记不直接转换为“有/无”，仅在机构名称精确匹配或领导链接唯一匹配时写入脚本序号。
- 机构主表命中规则记录后，`机构层级`、`所属省*`、`所属市`、`机构别称`和`备注`从对应规则记录带入；机构主表原有组织体系、目录链接、机构类型、机构名称、官网链接和领导链接保持不变。

## 使用方式

运行 `启动机构数据工作台.ps1`。脚本使用项目 uv 环境启动本地服务，并由系统默认浏览器打开 `http://127.0.0.1:8765`。发布会先备份正式机构主表；如果正式 TXT 在工作台外被修改，应先在工作台执行重新同步，再继续编辑或发布。

原 `Government_Agencies` 项目保留为迁移回退副本。后续机构脚本经检查后再逐项迁入，不直接复制旧生成器覆盖当前十二列主表。

## 维护脚本

维护脚本统一从项目根目录以模块方式运行，例如：

```powershell
D:\Desktop\software\uv-x86_64-pc-windows-msvc\uv.exe run python -m workspace.institution_catalog.maintenance.extract_provincial_government_institution_candidates
```

当前维护链条分为两类：

- 省级机构目录：抓取目录页、浏览器补抓、解析候选、检查 DOM、汇总并与规则主表核对。
- 主表链接维护：依据领导链接补官网、拆分链接核查任务、复核合并结果、填写高校领导链接。

凡是读写机构主表的脚本均严格校验十二字段；`脚本序号`直接表示是否已关联规则主表，不再读写旧字段`主表匹配`。省级目录汇总只生成审计和候选报告，不直接覆盖机构主表。
