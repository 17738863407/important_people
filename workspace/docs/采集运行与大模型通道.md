# 采集运行与大模型通道

> 适用任务：修改或运行批量采集、成功采集器记忆、HTTP/浏览器降级、代理处理、快照兼容、文章正文大模型或视觉大模型通道。执行这些任务前必须完整读取本文。

## 一、成功采集器记忆

1. `workspace\module\采集方式成功记录.txt`以四位脚本序号为稳定主键，只保留：`脚本序号、实际成功采集器、执行形态、最近成功时间`。
2. `实际成功采集器`只允许记录最终产生有效抽取结果的`raw_http、requests、playwright、chrome_cdp`。
3. Playwright子进程不是独立采集器，应记录为`实际成功采集器=playwright、执行形态=subprocess`。
4. 批量和单脚本联网运行均忽略页面脚本中历史遗留的`fetch_mode`、`preferred_fetch_mode`和`fetch.mode`。
5. 有成功记忆时优先使用该实际采集器，失败后继续全局降级链路；没有成功记忆时使用全局链路，成功并通过结果验收后才更新记忆。
6. 历史`online`只表示编排模式，不能反推出实际采集器；迁移时不得猜测写入。

## 二、全局采集链路

没有成功记忆时，固定尝试顺序为：

```text
raw_http → requests → Playwright → Chrome CDP
```

各采集器语义：

1. `raw_http`：基于`requests`获取当前HTTP原始响应，保留重试、请求头、SSL处理和编码识别，但不跟随页面脚本跳转，也不进入浏览器。
2. `requests`：增强HTTP采集，支持会话、轮换请求头、重试、SSL降级、编码识别及常见JavaScript `location`跳转；失败后不在该采集器内部进入浏览器。
3. `playwright`：只使用Playwright浏览器渲染；显式使用时不先尝试HTTP，也不自动改用Chrome CDP。
4. `chrome_cdp`：只连接项目的Chrome调试环境取得渲染DOM，作为全局链路末级通道。
5. 静态页面优先可复现HTTP；动态DOM使用浏览器；iframe先解析主页面`src`再抓取frame；稳定JSON/XHR直接解析接口。

## 三、Playwright、Chrome与失败降级

1. 浏览器顺序固定为无头Playwright优先、Chrome CDP最后；只有Playwright失败或渲染结果无效时才进入Chrome CDP。
2. Playwright必须使用项目uv环境及其安装的无头Chromium，不得把本机Google Chrome配置为Playwright的`executable_path`；首次同步环境后通过`uv run playwright install chromium`安装与锁定版本匹配的浏览器。
3. 本机Google Chrome只用于Chrome CDP末级通道；调试端口为`127.0.0.1:9222`，并使用项目根目录独立的`.chrome_cdp_profile`，不得使用默认用户数据目录。
4. Playwright子进程仅用于事件循环、greenlet、浏览器启动或上下文异常等运行环境故障；页面超时、网络错误或渲染无效时不重复启动子进程。
5. 在线失败必须保留各阶段真实失败原因，包括HTTP、Playwright进程内、Playwright子进程和Chrome CDP。
6. 页面失败、超时或防护不得以历史名单、旧输出、固定人物或静态结果替代。

## 四、代理与本机环境边界

1. 如果当前Python进程继承的代理变量指向`127.0.0.1`、`localhost`或`::1`，且对应端口确实无法连接，运行器只能在当前Python进程内临时移除失效代理变量并直连。
2. 不得修改Windows代理、用户环境变量或其他程序的网络设置。
3. 所有Python运行、测试、编译、依赖检查和Playwright任务通过当前系统可解析的`uv run`在项目uv环境中执行；若`uv`不在`PATH`中，则使用本机已核验的uv启动器。Playwright和Chrome CDP子进程默认继承当前`sys.executable`，只有设置`IMPORTANT_PERSON_PYTHON_EXE`时才使用显式解释器。
4. 需要连接可见Chrome或产生外部界面副作用时，必须确认当前任务确有需要。

## 五、批量运行产物

1. 批量运行不得把`online`记录为无法解释的单一成功阶段，必须记录实际成功采集器和执行形态。
2. 每次运行生成成功采集报告和失败报告。成功报告至少记录：脚本序号、机构、实际成功采集器、执行形态、实际尝试链路、有效记录数和耗时。
3. 失败报告记录完整失败原因；单脚本失败仍保留符合十二列契约的失败TXT。
4. 运行日志放入`workspace\log`，报告放入`workspace\reports`，抽取结果放入`outputs`。
5. 只有十二列结构、姓名和依据说明等质量门禁通过后，才能把采集器写入成功记忆。
6. 长任务显示进度；单文件失败时记录并继续，不中断整个批量审计或运行任务。

## 六、快照兼容边界

1. 生产默认链路是在线采集，页面脚本不得依赖默认快照获得数据。
2. 公共快照模块和显式快照分支仅作为旧代码兼容残留，不是生产默认路径。
3. 修改页面脚本时不得重新引入快照、快照路径或旧输出输入。
4. 移除公共快照代码必须作为独立核心任务：先审计显式引用，再逐文件删除；不得在普通页面修改任务中顺手扩大范围。

## 七、文章正文大模型抽取

仅当姓名、现任职务和简历混在正文中，DOM不存在稳定字段关系，规则和现有解析器无法可靠拆分时使用：

1. 采集层先在线取得页面并用选择器裁出最小正文范围，排除导航、相关新闻、历史任免、附件和模板噪声。
2. 发送给模型的是裁剪后的正文原文、机构和依据链接，不是整站HTML，不包含旧输出或固定人物名单。
3. 提示词要求只抽取正文明确陈述的当前人物和现任职务，不推断、不补全机构前缀、不把履历或分工当现职。
4. 模型返回严格结构化JSON，至少包含`source_order、name、raw_duty、evidence`；只有真实独立人物链接才能写入`detail_url`。
5. 原始`evidence`必须能在输入正文中逐字定位；程序接受结果前验证姓名、职务证据和顺序均可回指。
6. 模型结果先进入中间结果和审计；证据验证通过后才能进行允许的基本清洗并映射到十二列输出。
7. JSON解析失败、证据无法回指、人物归属不明或结果矛盾时标记失败或人工复核。

## 八、视觉人物抽取

只有领导信息确实承载在图片、扫描表格、长图或PDF截图中时使用视觉通道：

1. 优先读取图片旁可验证HTML文本；确为图片内容时，从当前页面动态发现并下载目标图片，不硬编码人物结果。
2. 记录图片URL、最终URL和SHA-256哈希；透明图片铺白底并转换为RGB，只有尺寸确有需要时按阅读顺序重叠切片。
3. 同一次响应同时返回逐字转写和`source_order、name、raw_duty、evidence、visual_span`等结构化JSON，禁止根据常识补全不可见内容。
4. 程序逐条验证姓名、职务和证据能够回指同次逐字转写，并检查顺序、重复记录、异常长姓名和非人物噪声。
5. 一个职务标题对应多人、跨行名单或多栏版面时，使用页面专属要求和切片参数维持真实版面归属，不得用历史名单补人或补职务。
6. 验证通过后才能映射到十二列输出；OCR或模型结果不得写回页面脚本形成固定人员表。
7. Codex对话视觉属于人工处理队列，不等同于可自动批量运行的生产链路。

## 九、模型配置与安全审计

1. API密钥只从环境变量或项目受保护的密钥配置读取，禁止写入Python源码、页面规则、提示词、日志、报告和Git。
2. endpoint、实际模型ID、超时、重试和并发均为运行时配置；项目侧模型名称不得代替账号实际模型ID。
3. 文章正文与视觉抽取使用各自版本化提示词，不共用含糊的万能提示词。
4. 提示词必须规定输入边界、字段定义、禁止推断、原文证据、顺序、严格JSON和失败返回格式。
5. 脚本生成器按显式任务清单工作：文章正文生成器会为`pending`任务生成主动拒绝运行的安全骨架，只有`verified`任务填写正文选择器后才生成可运行配置；视觉生成器要求任务为`verified`并填写图片选择器，否则拒绝生成。
6. 每次调用记录提示词版本/哈希、模型ID、输入内容哈希、响应原文、解析状态、证据校验、Token、耗时和错误，但不得记录密钥正文。
7. API失败、限流或权限受限时按单脚本规则记录并跳过，不得使用硬编码结果替代。

## 十、运行验收

涉及采集链路或模型通道的修改至少验证：

1. 实际尝试链路与配置一致，成功报告记录的采集器是真正产生有效结果的采集器。
2. Playwright和Chrome CDP边界正确，没有误用默认Chrome用户目录或可见浏览器。
3. 代理处理只影响当前Python进程。
4. 失败原因完整保留，失败TXT没有被删除。
5. 模型证据能回指同次输入或逐字转写，审计记录不含API密钥。
6. 十二列输出通过结构、姓名、依据说明、顺序和链接质量门禁。
