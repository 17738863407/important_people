# 重要人物职务规范处理规则

本项目固定使用“合并—清理—补全—扩充”四段链路：

1. `script3-职务规范1-合并.py`生成`职务规范1：合并.txt`；
2. `script3-职务规范2-清理.py`生成`职务规范2：清理.txt`；
3. `script3-职务规范3-补全.py`生成`职务规范3：补全.txt`；
4. `script3-职务规范4-扩充.py`生成`职务规范4：扩充.txt`。

四个阶段均处理十二列制表符TXT，记录数量和记录顺序必须保持不变。规则只使用当前行字段，不读取旧输出、历史名单或固定人物结果。

## 一、合并

- 输入：`outputs\成功`中的单脚本十二列TXT。
- 输出：项目根目录下的`职务规范1：合并.txt`。
- 只保留一次十二列表头，保持单个文件内部人物顺序。
- 不清理、不补全、不扩充职务。

## 二、清理

### 1. 职责

清理阶段只负责确认真实职务、去除噪声、划分职务片段和统一标点，不补入地域或机构主体，也不把简称变为全称。

### 2. 清理内容

1. 从当前行`依据说明`生成`职务*`；`依据说明`为空或以`抽取失败：`开头时不生成职务。
2. 删除`姓名*`中的全部空白字符。
3. 删除HTML标签、制表符、换行、零宽字符和排版空白。
4. 删除开头的`职务、现任职务、职位、现任、现为、担任`等固定标签。
5. 删除职务开头或特定尾部重复出现的当前姓名。
6. 排除能够明确识别的履历日期、职责尾句、网页分组标签和独立状态词。
7. 将`兼任、并任、同时担任`等连接形式转换为职务分隔边界，不补造网页没有表达的职务。
8. 删除所有圆括号及其中内容；方括号和尖括号只删除符号并保留正文。
9. 将职务分隔符统一为中文顿号`、`，删除重复分隔符并保持原始先后顺序。
10. 对能够确定边界的粘连职务进行拆分，例如`党委委员副主任市疾控局局长`拆为`党委委员、副主任、市疾控局局长`，`董事党组副书记`拆为`董事、党组副书记`，`董事长党组书记`拆为`董事长、党组书记`；不得在边界不明确时盲目切分。

### 3. 输出约束

- 清理阶段只允许修改`姓名*、职务*`。
- 输出：`职务规范2：清理.txt`。
- 审计报告：`workspace\reports\职务规范2：清理审计报告_YYYYMMDD_HHMMSS.txt`。
- 日志：`workspace\log\职务规范2：清理日志_YYYYMMDD_HHMMSS.txt`。

## 三、补全

### 1. 总原则

清理阶段确认某个片段是真实职务后，补全阶段必须使每一个非空职务片段脱离前后文也能识别其任职主体。

除第18条规定的确定性省名前缀去冗余外，补全只增加原职务缺少的地域、行政层级、机构主体或隶属关系，保留原有机构简称；不得在本阶段把`发改委、国资委、卫健委、住建局、工信局、管委会`替换成对应全称。

### 2. 主体补全顺序

1. 职务片段已经具有明确主体时保持不变，但符合第18条的省名前缀去冗余规则时按该条处理。
2. 已有机构简称但缺少地域或层级时，只补地域或层级。例如`发改委副主任`补为`长春市发改委副主任`。
3. 完全没有主体时，优先继承同组中最近且语义相容的明确主体。
4. 同组没有可继承主体时，使用当前行`机构`字段补全。
5. 省长、市长、州长、区长、县长等行政首长职务使用可验证的行政区名称作为主体。
   行政区全称和职务名称中的行政层级字样必须分别保留，例如`河北省省长、石家庄市市长、朝阳区区长、正定县县长`；不得错误合并为`河北省长、石家庄市长、朝阳区长、正定县长`。
   原文已经写成`玉溪市长、河北省长`等重叠省略形式时，也应恢复为`玉溪市市长、河北省省长`；但`副市长、常务副市长、代市长`中的“市”属于职务本身，不得误识别为地名。
6. 明确属于其他机构的职务保留该机构主体，不得错误改为当前行机构。
7. 每个职务片段分别补全，不得只让第一项职务完整。
8. 必须区分机构名称末字与职务结构：`商务厅厅长`中的第二个`厅`属于职务`厅长`，必须保留；`商务厅党组成员`中的`党组成员`直接隶属于商务厅，不得写成`商务厅厅党组成员`。`局党组、委党组、院党组、厅党委、局党委`等同类结构按相同原则处理。
9. `省、自治区、区、市`作为相对地域占位词时，必须结合当前行地域或同组最近出现的区县名称补全，例如`市人才服务中心`补为`长春市人才服务中心`，`区知识产权局`补为`西藏自治区知识产权局`。
10. `政治部、非税收入核算中心`等当前机构内部单位必须补入当前机构主体；不得因文本中已经出现`部、中心`等机构词就误判为主体完整。
11. `组织部、宣传部、统战部`等党委组成部门必须继承对应党委主体，例如`安徽省委组织部`、`重庆市委统战部`。
12. `地震局、药监局`等具有独立任职主体的机构简称按当前地域层级补全，不得错误拼接为当前机构的内部部门。
13. `驻厅、驻委、驻局、驻院、驻部`等派驻纪检监察表述必须同时补明派出机关和被监督机构。省级统一形成`某省（自治区）纪委监委驻省级目标机构纪检监察组职务`，市级形成`某市纪委监委驻市级目标机构纪检监察组职务`，中央国家机关形成`中央纪委国家监委驻目标机构纪检监察组职务`；不得写成`当前机构驻厅（委、局、院）纪检监察组职务`。
14. 新疆语境中的`兵团`默认补全为`新疆生产建设兵团`，包括兵团党委、兵团所属局和兵团所属团体；例如`兵团商务局局长`补为`新疆生产建设兵团商务局局长`。
15. `办公厅、常委会、常务委员会、调查统计司、医政司、新闻局、党支部、队伍建设指导部、宣传教育培训部`等相对机构名称必须结合当前机构、同组上文及上下级结构补全；不得仅因已经出现`厅、会、司、局、部`等字样就判定主体完整。
16. `常务副馆长、常务副院长、第一副院长`等带修饰语的领导职务仍属于无主体职务，必须补入对应馆、院或学院名称。
17. 原文地域名称若是当前行明确地域的残缺后缀，例如`川市退役军人事务局`而当前机构和所属市均明确为`银川市`，可以确定性恢复为`银川市退役军人事务局`；只有能够由当前行地域唯一验证时才允许修复。
18. 当前行`所属省*`和`所属市`均有内容，且职务片段精确以“所属省* + 所属市”开头时，删除该职务片段中的省名前缀，避免重复表达可由所属市唯一确定的上级省份；`所属市`可以是市、自治州或其他已明确的地级地域，不限制名称后缀。例如`所属省*=青海省、所属市=海东市`时，`青海省海东市中级人民法院副院长`规范为`海东市中级人民法院副院长`；`所属省*=青海省、所属市=海北藏族自治州`时，`青海省海北藏族自治州人民检察院副检察长`规范为`海北藏族自治州人民检察院副检察长`。所属市为空或职务中的地域与当前行所属市不一致时，保留省名前缀。

### 3. 示例

```text
总农艺师 + 机构=吉林省农业农村厅
→ 吉林省农业农村厅总农艺师
```

```text
宁波市农业农村局党组成员、总农艺师
→ 宁波市农业农村局党组成员、宁波市农业农村局总农艺师
```

```text
发改委副主任 + 机构=长春市发展和改革委员会
→ 长春市发改委副主任
```

```text
南宁市农业农村局党组成员、总农艺师、南宁市科协副主席
→ 南宁市农业农村局党组成员、南宁市农业农村局总农艺师、南宁市科协副主席
```

`总农艺师、总工程师、总经济师、总会计师、总审计师、总规划师、总畜牧师、教授、研究员、巡视员、调研员`等仅为示例。补全不得依赖封闭的职务白名单；凡经清理保留的真实职务，原则上都必须具有明确主体。

### 4. 输出约束

- 补全阶段只允许修改`职务*`。
- 输出：`职务规范3：补全.txt`。
- 审计报告：`workspace\reports\职务规范3：补全审计报告_YYYYMMDD_HHMMSS.txt`。
- 日志：`workspace\log\职务规范3：补全日志_YYYYMMDD_HHMMSS.txt`。

## 四、扩充

### 1. 总原则

扩充阶段不再补地域或主体，只处理已经完整、能够确定任职主体的机构简称与全称，以及省、市政府行政首长职务的不同规范写法。保留原文职务，并补充语义等价的简称、全称或政府名称写法；不得改变职务性质、级别、顺序或任职主体。扩充使用脚本内置稳定规则，不读取外部别称文件。

### 2. 示例

```text
长春市发改委副主任
→ 长春市发改委副主任、长春市发展和改革委员会副主任
```

```text
国务院国资委主任
→ 国务院国资委主任、国务院国有资产监督管理委员会主任
```

```text
北京城市副中心管委会副主任
→ 北京城市副中心管委会副主任、北京城市副中心管理委员会副主任
```

```text
吉林省农业农村厅总农艺师
→ 吉林省农业农村厅总农艺师
```

最后一例没有需要扩充的机构简称，保持不变。

### 3. 扩充边界

1. 简称、全称或政府名称写法必须能根据当前行`机构`字段或脚本内置规则确定对应关系。
2. 不执行脱离当前机构上下文的全局字符串替换。
3. 原文职务和新增等价写法必须相邻，并保留原文职务。
4. 省、市政府行政首长职务可依次补充“地区+职务”“地区+政府+职务”“地区+人民政府+职务”等明确写法。
5. 同一职务不得重复扩充，完全相同的结果只保留一次。
6. 扩充不得改变职务性质、级别、顺序或任职主体。

### 4. 输出约束

- 扩充阶段只允许修改`职务*`。
- 输出：`职务规范4：扩充.txt`。
- 审计报告：`workspace\reports\职务规范4：扩充审计报告_YYYYMMDD_HHMMSS.txt`。
- 日志：`workspace\log\职务规范4：扩充日志_YYYYMMDD_HHMMSS.txt`。

## 五、通用质量门禁

1. 十二列表头及列序必须一致。
2. 输入输出记录数量和顺序必须一致。
3. 每个阶段只能修改该阶段授权的字段。
4. 单行失败时记录原因并继续处理；全量质量门禁失败时脚本必须以失败状态退出。
5. 审计报告记录处理前职务、处理后职务和所用规则，保证结果可回指。
