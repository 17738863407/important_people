# 待处理视觉结果回填

本技能仅用于当前项目的 Codex 对话视觉人工处理队列，不替代自动生产采集链路。

## 开始前

完整读取项目 [AGENTS.md](../../../AGENTS.md)、[数据与输出契约](../../../workspace/docs/数据与输出契约.md) 和 [采集运行与大模型通道](../../../workspace/docs/采集运行与大模型通道.md)。涉及适配器修改时另读项目的适配器开发文档；处理失败结果不自动授权修改适配器。

## 扫描与定位

- 从项目根目录通过项目 uv 环境运行 `uv run --no-sync -- python .agents/skills/resolve-llm-vision-outputs/scripts/scan_llm_vision_outputs.py`，默认只读扫描 `important_people/outputs`。
- 可传入以 `important_people/` 开头的项目逻辑路径；项目外目录通过明确的环境变量 `IMPORTANT_PEOPLE_VISION_OUTPUT_DIR` 传入。扫描日志写入 `workspace/log`。
- 扫描器按四位脚本序号递归查找 `site_adapters` 中的同序号脚本。多个候选时全部列出，不自动选取首个；无匹配、重复序号或历史八列表头均须查明后再处理。
- 从当前规则主表取得机构、领导入口和地区等业务字段，从对应适配器读取现行图片选择器与视觉策略。旧输出只用于发现待处理任务，不作为人物数据来源。

## 当前图片识别与回填

1. 使用项目现有 HTTP 采集能力获取当前在线页面，动态发现目标图片并记录图片 URL、最终 URL 和 SHA-256。需要浏览器界面交互时遵守用户当前授权边界。
2. 使用当前对话的 `view_image` 查看本次下载的图片，只转写可见文字，并同时记录图片阅读顺序、姓名、原始职务证据及所在区域。不得用常识、历史输出或固定名单补人补职务。
3. 每个人物的姓名与职务证据必须能回指本次逐字转写及图片区域。模糊、归属不清或未通过验证的结果继续保留为失败或人工复核。
4. 验证后通过项目现行导出能力写回原失败 TXT，严格使用十二列：`姓名*、职务*、排序*、职级*、所属省*、所属市、依据链接、依据说明、维护人、机构、详情页链接、脚本序号`。`职务*`、`职级*`、`维护人`留空，原始职务证据写入`依据说明`；四位脚本序号与机构信息取自规则主表，排序继承图片版面顺序。
5. 图片不能证明独立人物详情页时，`详情页链接`留空。图片识别来源、逐字转写和验证记录放入项目日志或报告，不向输出增加解析器、选择器等旧列，也不把识别结果写入适配器。
6. 回填后验证十二列表头、人物顺序、证据及来源链接。不得未经明确要求调用外部 OCR、模型 API 或读取 API 密钥。临时图片保留在任务临时目录，需要清理时遵守全局备份和回收站核验规则。
